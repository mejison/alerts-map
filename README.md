# ВАРТА — карта тривог України

Адаптивний вебсайт українською: тривоги по районах, відкриті повідомлення про БпЛА та інші повітряні загрози, WebSocket, резервний REST, фільтри й локально збережений обраний регіон. Реальні дані NEPTUN; демонстраційних тривог немає.

## Запуск

Node.js 22.13 або новіший.

```sh
npm install
npm run dev
```

Відкрийте адресу Local, яку покаже сервер (Next.js зазвичай http://localhost:3000). Для попереднього Vinext/Cloudflare dev-сервера використовуйте `npm run dev:cloudflare` (порт 5173).

```sh
npm test
npm run typecheck
npm run build
```

Проєкт використовує React 19, TypeScript, Vinext/Vite та Cloudflare Workers. Вхідна сторінка — app/page.tsx, стилі — app/globals.css, живе підключення — lib/use-live.ts, нормалізація — lib/live-core.mjs, серверні провайдери — lib/providers.ts.

## Netlify

Підключіть цей репозиторій, production branch `main`. Налаштування з `netlify.toml` мають пріоритет над попередньою командою та publish directory в інтерфейсі:

- Build command: `npm run build:netlify`.
- Publish directory: `dist-netlify`.
- Functions directory: `netlify/functions`.
- Node.js: 22.

Це окрема Vite-збірка тієї самої карти. `/api/live` обслуговує Netlify Function зі спільними серверними провайдерами, WebSocket працює без змін. Збережено додану раніше можливість звичайної Next.js-збірки: `npm run build` / `npm start`. Для Cloudflare/Sites — `npm run build:cloudflare` / `npm run start:cloudflare`; під час пакування Sites задайте `VARTA_BUILD_TARGET=cloudflare`, і стандартний build helper використає Vinext. Netlify вибирає свою збірку з `netlify.toml`.

Помилка `Your publish directory does not contain expected Next.js build output` виникала через автоматичний Next.js Runtime, який шукав `.next`, хоча Vinext створює Worker-збірку. `NETLIFY_NEXT_PLUGIN_SKIP=true` у конфігурації пропускає цей плагін (підтримується Runtime 5.12+). Якщо в Netlify вручну закріплено старіший плагін, вимкніть його в Project configuration → Build plugins. Після push запустіть новий deploy, якщо автоматичні деплої вимкнені.

Перевірка всієї збірки та пакування функцій локально:

```sh
npx netlify-cli build --offline
```

## Мобільний застосунок і push

ВАРТА — PWA: `public/manifest.webmanifest`, окремі іконки та `public/sw.js`. Встановлення доступне з кнопки дзвіночка в шапці. На Android — «Встановити застосунок»; на iPhone/iPad з iOS 16.4+ — Safari → «Поширити» → «На початковий екран», потім відкрити встановлену ВАРТУ. Це встановлюваний вебзастосунок, без публікації в App Store / Google Play.

Push використовує **OneSignal Web SDK v16**, App ID `3471bd1d-58b7-4529-903a-aca7f27149f5`. Спільний клієнтський завантажувач `lib/onesignal.ts` підключає офіційний скрипт `https://cdn.onesignal.com/sdks/web/v16/OneSignalSDK.page.js` один раз на сторінку. Автоматичні permission prompts і стандартний дзвіночок вимкнені: дозвіл запитується лише кнопкою ВАРТИ. У OneSignal зберігається тег `varta_region`; основний вибір області зберігається також на сервері.

Service worker OneSignal розташований за постійною адресою `/push/onesignal/OneSignalSDKWorker.js` зі scope `/push/onesignal/`. PWA-кеш використовує окремий `/sw.js` зі scope `/`. OneSignal сам обробляє push і відкриття потрібної області після натискання на повідомлення. Власний Web Push/VAPID-відправник видалено, старі VAPID-змінні більше не використовуються.

Історичний шар руху загроз збирається серверною Netlify Function раз на 5 хвилин у Netlify Blobs. Для нього зберігаються лише добові лічильники в географічних клітинках 1° (приблизно 70–110 км), без ID, точних координат і послідовностей окремих цілей. Дані показуються після закриття доби та щонайменше 24-годинної затримки; клітинка з менш ніж 12 спостереженнями приховується. Архів старший за 30 днів автоматично видаляється. Увімкнення історичного шару ховає живі позначки й надані джерелом лінії, щоб їх не накладати на архів.

Активація:

1. У OneSignal → Settings → Push & In-App → Web перевірте Site URL `https://alerts-map.netlify.app` і налаштування Custom Code. OneSignal прив'язує web app до домену; localhost та приватна копія Sites не є цим доменом.
2. У OneSignal → Settings → Keys & IDs отримайте **App API Key** для цього App ID. Додайте його в Netlify → Environment variables як `ONESIGNAL_REST_API_KEY`, context **Production**. Якщо тариф дозволяє scopes, оберіть **Functions**. Не використовуйте `VITE_` / `NEXT_PUBLIC_` і не додавайте ключ до репозиторію.
3. Після зміни змінних виконайте новий deploy. `/api/push/config` має показувати `provider: "OneSignal"`, правильний `appId` та `enabled: true`. Цей endpoint ніколи не віддає App API Key.
4. Оберіть область → «Увімкнути сповіщення» → дозвольте їх браузеру → «Перевірити». Тест надсилається сервером через OneSignal, не через локальний toast. Попередню VAPID-підписку потрібно поновити через цей інтерфейс.

Scheduled function `push-dispatch` перевіряє NEPTUN щохвилини. Вона надсилає повідомлення через OneSignal REST API `/notifications`, адресуючи тільки конкретний `include_subscription_ids`, а не всіх користувачів застосунку. Netlify Blobs зберігає OneSignal Subscription ID, область, секретний токен керування у вигляді хешу та останній стан. Власні push endpoints і ключі шифрування браузера не зберігаються. App ID є публічним; App API Key використовується лише сервером.

Підписка охоплює область та всі її райони. Відбій надходить, коли активних тривог в області більше немає; зміна окремого району за наявності інших тривог не є відбоєм. Початковий стан зберігається без вигаданого переходу. Зміна червоного/жовтого рівня також сповіщається. Усі повідомлення посилаються на NEPTUN.

Некоректна або неповна відповідь NEPTUN скасовує перевірку без зміни стану. Умовні записи та lease захищають від паралельних запусків, а збережений `idempotency_key` — від повторної доставки при повторенні запиту OneSignal. Відповідь OneSignal без message ID не вважається успішною відправкою. Відписка викликає OneSignal `optOut()`, прибирає тег області та видаляє Subscription ID із серверного запису. API не віддає список підписників; зміна/видалення потребують секретного токена пристрою. Ідентифікатори пристроїв і секрети не логуються.

Стан перевіряється раз на хвилину, тому дуже короткі переходи між перевірками можуть бути пропущені. Доставка залежить від мережі, браузера, режиму фокусування та ОС; термін життя повідомлення — 2 хвилини. Офіційні сигнали мають пріоритет. Для великої кількості підписок потрібна черга: поточна функція призначена для початкового запуску й обмежена часом виконання Netlify Functions.

Офлайн-кеш містить лише оболонку, шрифти й геометрію. API тривог та push API ніколи не кешуються; за відсутності зв'язку карта показує непідтверджений стан.

## Джерела

NEPTUN працює без ключів: https://neptun.in.ua/developers . Атрибуція обов'язкова; вона є на карті. Фонове опитування відбувається раз на 15 с; WebSocket передає зміни одразу. Позначки є даними відкритого моніторингу з можливою похибкою, не радаром. Застарілі або недоступні дані явно позначаються.

Прямі адаптери alerts.in.ua та UkraineAlarm підготовлено, але без особистих ключів не перевірено інтеграційно. Ключі потрібно отримати у провайдерів. Для локальної роботи скопіюйте .env.example у .env.local та виберіть один ALERT_PROVIDER. Для розгортання задайте ці самі змінні в секретах середовища хостингу. Секрети використовуються лише на сервері. Перед масовим використанням ключів реалізуйте спільний кеш/централізований збирач, щоб гарантувати rate limit між Worker-ізолятами.

Карта завжди лишається інформаційним сервісом. Пріоритет мають офіційні сигнали тривоги.
